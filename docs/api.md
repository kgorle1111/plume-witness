# Open data: the static JSON Plume Witness serves

There is no server and no API key. The site is static files on GitHub Pages; every number on a page comes from one
of the files below, and you can fetch them directly. Nothing here is live: each file is a snapshot regenerated by
the pipeline and committed to the repo.

Base URL: `https://kgorle1111.github.io/plume-witness/` (all paths below are relative to it).

```bash
# the 2024-2025 spike log, filtered to benzene rows with a matched company report
curl -s https://kgorle1111.github.io/plume-witness/spikes.json \
  | python3 -c "import json,sys; d=json.load(sys.stdin); [print(r['date'], r['site'], r['value_ppb'], r['matched_incident']) for r in d['rows'] if r['status']=='reported']"
```

## Read this first

- **Not findings.** "Not yet reported" and "no report after the deadline" are questions to ask, not findings about a
  facility: Texas requires a report only above a reportable quantity (30 TAC 101.201), and air readings cannot
  measure how much was released.
- **Wind at one monitor cannot tell facilities apart.** The upwind corridor is geometry (the hourly wind direction
  at one monitor, +/-22.5 degrees, up to 15 km), not a dispersion model. Being upwind of a spike is not evidence of anything.
- **Provisional data.** TCEQ labels its hourly AutoGC values provisional and subject to change.
- **Local times.** Monitor hours are CST as TCEQ publishes them. Company-report times are local at the facility, as TCEQ
  publishes them (CST or CDT).

### `event.json` and `nights/<id>.json`

Schema `plume-witness.event/v1`, defined and validated by [`pipeline/contract.py`](../pipeline/contract.py) and mirrored
for the web app in [`web/src/types.ts`](../web/src/types.ts). `nights/<id>.json` files use the same schema, so any
tool that reads one reads all.

| Field | Meaning |
|---|---|
| `label` | `real` (public data) or `fixture` (invented, for tests; never published on the site) |
| `compound` | `{name, aqs_param, units}`; `aqs_param` 45201 is benzene, 43218 is 1,3-butadiene; units are ppb-v |
| `monitors[]` | Each state monitor that day: `site_id`, `name`, `lat`, `lon`, `baseline` (7-day median), `peak`, `triggered`, `hourly[24]` as `{hour_cst, value, flag}` |
| `wind` | `{site_id, hourly[24]}` of `{hour_cst, from_deg, speed_mph}`: degrees the wind blows **from**. When it is not the flagged monitor's own weather-station (met form) wind it also has `source` (`own_autogc`: the monitor's own AutoGC resultant wind; `borrowed_met` / `borrowed_autogc`: a nearby monitor's, named by `site_id`) and a plain `source_note`; a borrowed wind also adds a line to `cannot_say` |
| `detection` | The trigger: `{site_id, hour_cst, value, baseline, rule}`. Rule: value >= max(10 x baseline, 10 ppb) |
| `facilities[]` | EPA ECHO major sources near the monitor: `id` (EPA registry id), `name`, `lat`, `lon`, `distance_km`, `bearing_deg`, `alignment`, `in_corridor`, `rank` (nearest first; not a likelihood). One EPA registry id can hold several permit holders at one address: such a site's `name` lists every holder ECHO gives it, sorted and joined by " / ", as its facility page does. On the facility whose report matched, `name` is the filer as the TCEQ report names it, and `echo_names[]` lists every name ECHO gives that site |
| `corridor` | `{origin_site_id, half_width_deg, max_km, wind_from_deg[]}` |
| `record_check` | The state-record check: `status` (one of `reported`, `reported_late`, `not_yet_reported`, `no_report_after_deadline`, `reported_mismatch`, `search_incomplete`, `reported_nrc`; as `status`, `reported_late` comes from the T+14d check alone: a FINAL report dated more than 14 days after the event ended (an initial notice filed more than 24 h after discovery makes only the T+24h entry of `checks[]` `reported_late`); `reported_nrc` means no STEERS report in the corridor and window, but a National Response Center report there lists the compound), `incident`, `matched_facility_id`, `source_url` (TCEQ record), `reported` (the matched report: `facility`, `compound` and `pounds` (on a match, the monitored compound and its pounds summed over the report's emission points, for the whole release; on `reported_mismatch`, the report's first contaminant line), `start_local`, `end_local`, `match_basis`, `cause`), `day_incidents[]` (every STEERS report that day with where it sits), `checks[]` (T+24h and T+14d, always the STEERS checks), `search_scope`; with `reported_nrc` only, `nrc` (the NRC report: `report` number, `source_url` of the NRC yearly file, `company`, `incident_local`, `material`, `amount` (null when NRC gives none), `unit`, `located_by`); `unplaced_other_reports[]` when an NRC report naming the compound in the match window could not be placed on the map (it blocks an absence claim) |
| `packet` | English and Spanish evidence summary drafts: a person reviews and files; nothing is sent automatically |
| `cannot_say[]` | The limits that go with this night |
| `provenance[]` | Every raw file used: `file`, `url`, request `params`, `bytes`, `sha256`, `fetched_at` |

Provenance: TCEQ AutoGC hourly yearly summaries and site meteorology, TCEQ STEERS emissions-event reports, EPA ECHO
facility locations. Facility coordinates are as ECHO publishes them and may be approximate.

Second report source: US Coast Guard National Response Center (NRC) incident reports, CY2024 and CY2025 yearly files
from nrc.uscg.mil, Harris and Jefferson counties (`data/raw/nrc/`; `uv run python -m pipeline.nrc`). An NRC report counts
only when STEERS has no report in the corridor and window, it started inside the match window (NRC gives no end time),
it names the compound (CAS number, or a material name that names it), and it sits in the corridor by its own
coordinates or by the same ECHO name/address rule the STEERS check uses. NRC marks these data initial and not validated.

### `nights/index.json`

Array of `{id, date, site, site_name, compound, value, hour_cst, status, search_complete}`. `id` is the night's file
stem and the app's `?night=<id>` parameter: `<date>_<aqs_param>_<site_id>`. `value` is ppb at `hour_cst` (CST).

### `spikes.json`

Schema `plume-witness.spikes/v1`, exported by [`pipeline/spikes.py`](../pipeline/spikes.py). Top level: `trigger`,
`corridor`, `years`, `units`, `tceq_search_page`, `summary` (`spikes`, `spike_days`, `by_status`,
`known_missed_reports`), `rows[]`. Each row: `night_id`, `date`, `hour_cst`, `site_id`, `site`, `lat`, `lon`, `param`,
`compound`, `value_ppb`, `baseline_ppb`, `ratio`, `status`, `reports_that_day`, and when present `reason`,
`reason_code`, `matched_incident`, `report_url`. Rows carry counts and ids, never a facility name. 283 of 468 rows are
`search_incomplete` (the record check could not finish). `reason_code` is why, and `reason` is its English sentence
(`pipeline/spikes.py` REASONS; the site shows a translated label for the code). The codes, in the order they are checked:
`calm_wind` (under 3 mph, no corridor drawn), `report_not_placed` (a report open at that hour, from that day or
earlier, could not be placed on the map), `earlier_search_incomplete` (the 30 days before were not all searched),
`day_search_incomplete` (TCEQ's search for that week did not return every row) or `no_wind`. The backtest that measures how
well this check works is in [`backtest.md`](backtest.md): the pipeline matched 1 of 77 company-reported releases end to end.

### `coverage.json`

Written by [`pipeline/coverage.py`](../pipeline/coverage.py) from TCEQ's AutoGC site list
(`data/raw/texas_coverage/agc_form.html`) and each region's published `spikes.json`. Top level: `generated` (date),
`trigger`, `sites[]`. Each site: `site_id`, `name`, `county`, `region_key` (null for a monitor with no 2024-2025 data),
`lat`, `lon`, `has_data`, `wind_source` (`met`: its own weather-station wind; `autogc`: the AutoGC form's resultant
wind; `borrowed`: the nearest monitor's in its region; null with no data), `years` with hourly values,
`max_benzene_ppb`, `max_butadiene_ppb` (highest hourly values, 2024-2025, null with no data), `spikes` and
`by_status` (that monitor's rows in its region's spike log). A monitor with readings but `spikes: 0` never crossed the
trigger in 2024-2025.

### `rose.json`

Per monitor and compound, the share of high hours by 30-degree wind-from sector (conditional probability function,
2024-2025, hourly, wind >= 3 mph), from each monitor's own wind only (`wind_source`: `met` form, or the `autogc` form's
resultant wind where the site has no met wind). `method` documents the thresholds. It shows which direction chronic high readings arrive
from; it does not name a source. Code: [`pipeline/rose.py`](../pipeline/rose.py).

### `people.json`

Census tracts whose internal point lies within 3 km of each monitor, with population, households, Hispanic share,
Spanish spoken at home, limited-English households, under 18, 65 and over, and median household income (US dollars).
Source: ACS 2024 5-year, Harris County tracts; each file's URL and SHA-256 are in `sources[]`. Tract membership is by
internal point, not area overlap. See [`people.md`](people.md).

### `tri.json`

EPA Toxics Release Inventory, air releases (stack plus fugitive) of benzene and 1,3-butadiene, 2020-2024, in pounds
per year, for 194 ECHO major facilities within 15 km of a monitor. `facilities.<registry_id>.years.<year>.<compound>`
holds `stack_lbs`, `fugitive_lbs`, `total_lbs`; a `null` means the form gave no number, which is not zero. Only 121 of
the 194 link to a TRI facility id; `facilities.<id>.status` and `reason` say how each one linked or why not, and
`unlinked_tri_reporters` lists reporters in the same counties that did not link. These are self-reported annual
estimates of routine releases: not measurements, not events. See [`tri.md`](tri.md).

### `facilities/index.json` and `facilities/<registry_id>.json`

Schemas `plume-witness.facilities-index/v1` and `plume-witness.facility/v1`, generated by
[`pipeline/facilities.py`](../pipeline/facilities.py) (`uv run python -m pipeline.facilities`, cache only, no network).
`<registry_id>` is the 12-digit EPA registry id, the same `id` the `facilities[]` array in a night file uses.

`index.json`: `universe`, `report_years`, `coverage`, `caveats[]`, `facilities[]` of `{id, name, address,
distance_km, nearest_monitor, reports, tri_years, matched_nights}`. `coverage` says how many cached TCEQ reports could
be tied to a facility: of 315 cached detail pages, 251 are placed on a facility in this set, 6 on an ECHO facility
outside it, and 58 on none (name or address matched no single ECHO site; they appear on no page).

Each facility file:

| Field | Meaning |
|---|---|
| `registry_id`, `name`, `address`, `lat`, `lon` | ECHO's record, name and address as published (upper case). A site ECHO lists under several major-source names (7 of 194) is named by all of them, joined by " / " |
| `distance_km`, `nearest_monitor` | Distance to the nearest of the 12 monitors |
| `echo_url` | EPA ECHO facility report |
| `reports_to_state.reports[]` | Emissions-event reports the facility filed with TCEQ that started in 2024-2025: `incident`, `filed_by` (the regulated entity named on the TCEQ report), `event_type` (as TCEQ labels it) and `event_type_code` (e.g. `emissions_event`), `start_local`, `end_local` (local time), `benzene_lbs`, `butadiene_lbs` (summed over emission points; 0 = not listed), `cause_excerpt` (the facility's own words, at most 200 characters; withheld, with `cause_withheld: true`, if it contains a word this project does not republish), `url` (the TCEQ record) |
| `reports_to_epa` | The facility's `tri.json` entry: `status` (a code: `tri_data`, `no_tri_id` or `linked_no_benzene_or_butadiene_form`), `reason` (English), `tri_ids`, `years` |
| `matched_nights[]` | Replayed nights where the facility sat in the upwind corridor **and** its own report was the match (status `reported`): `night_id`, `date`, `hour_cst`, `monitor`, `compound`, `value_ppb`, `incident`, `distance_km`, `bearing_deg` |
| `caveats[]` | Always includes: "Being upwind of a spike is not evidence of anything; wind at one monitor cannot tell facilities apart." |

What is deliberately not here: any list of nights a facility was upwind with no matching report. One monitor's wind
cannot tell facilities apart, so that list would read as blame. A test fails the build if such a field appears.

Caveats specific to this file: pounds are the facility's own estimates from the TCEQ record; the compound totals are
only for benzene and 1,3-butadiene (the TCEQ record lists every compound); an empty `reports` list means no report in the
cached pages, not that none exists.

## Embedding a night

`?night=<id>&embed=1` renders a compact view for an `<iframe>`: the map, one step (Detect, Trace or Check, chosen by the
URL hash such as `#trace`) in a sentence or two, and an "Open in Plume Witness" link to the full replay. The
"Embed this night" button on any replay shows the iframe HTML to copy. The embed carries the same limits: it makes no
finding about any facility.

## Regenerating

```bash
uv run python -m pipeline.backtest && uv run python -m pipeline.spikes   # spikes.json
uv run python -m pipeline.tri                                            # tri.json
uv run python -m pipeline.facilities                                     # facilities/
uv run python -m pipeline.coverage                                       # coverage.json (after every region's spikes)
```

Every raw file the pipeline reads is in `data/raw/` with its URL and SHA-256 in the neighbouring `provenance.json`.
